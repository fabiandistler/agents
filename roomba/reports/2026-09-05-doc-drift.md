# roomba `doc-drift` — 2026-09-05

**Residual question:** does the documentation still describe what the code does?

**Method.** Per `references/jobs.md`, a claim counts only when it is *executed* or
mechanically compared against the thing it describes — never when it merely reads stale.
This repository is neither an R package nor a Python package, so `run_examples()`,
vignette builds and doctests do not apply. The executable surface here is:

- shell examples in docs → run them, compare against the documented output
- paths, filenames and script names cited in docs → resolve them on disk
- flags and subcommands of `scripts/*` and `install.sh` → `--help`, compare
- manifests (`skills.json`, `marketplace.json`, `plugin.json`) → compare against
  the directories they enumerate
- numeric claims (task counts, budgets, limits) → count / read the constant

Claims that could not be executed or mechanically compared are not reported.

**Baseline:** green before and after — all 10 commands from `ROOMBA.md` → *Baseline*
(identical to `.github/workflows/ci.yml`), each `rc=0`.

**Pre-stage:** `doc-drift` has none (`ROOMBA.md` job table, column *Pre-stage* = no).

### 1 — `README.md`: `skills/` "each subdirectory has a `SKILL.md`" is false — **fixed**

`README.md` → *Contents*:

> `skills/` | All installable skills (each subdirectory has a `SKILL.md`), …

Executed:

```console
$ ls skills/skill-creator/
eval-viewer  scripts  tests
```

`skills/skill-creator/` has no `SKILL.md`. It is the leftover of
`ffe7cdc Remove guideline-distillation, skill-creator and zettelkasten skills`, which
removed the skill but kept the directory; `ROOMBA.md` still points at
`skills/skill-creator/tests` as a live test location, so the directory is not itself the
error. `AGENTS.md:9` already phrases the same rule correctly ("Each directory under
`skills/` **that contains** a `SKILL.md` file is a self-contained skill"); the README
sentence is the one that over-claims.

Fixed by matching the README to the `AGENTS.md` phrasing. Removing the directory would be
a repository change, not a documentation change, and is out of this job's scope.

### 2 — `README.md`: the namespaced-plugin-skill example does not exist — **fixed**

> Plugin skills are namespaced (`architecture:adr-workflow`).

`architecture:adr-workflow` is not a plugin skill. Executed:

```console
$ ls -l plugins/architecture/skills/
architecture -> ../../../skills/architecture
```

Only the router registers at plugin top level; `adr-workflow` rides nested under
`skills/architecture/members/`. `scripts/check_plugins.py:182-187` states the same rule

under the router"). The example dates to `7e3b2e3`, which predates routers (`4bcb425`).

Fixed by using a real example (`communication:documentation`) and naming what a routed
category namespaces instead (`architecture:architecture`).

### 5 — `AGENTS.md`: the AI & ML section does not say it is routed — **fixed**

`AGENTS.md:60` carries "Registered through the [`architecture`](…) router." under
*Architecture & design*. The AI & ML section has no such line, although `ai-ml` is a
router as well:

```console
$ grep -m1 '^activation:' skills/ai-ml/SKILL.md
activation: router
$ ls skills/ai-ml/members/
llm-application-engineering  ml-project-lifecycle
```

`check_recall.py --dry-run` reports both as routed: `routed categories: ai-ml, architecture`.

History confirms the omission rather than an intentional asymmetry: the line was
introduced with the architecture router (`4bcb425`), and `306ea53` added the further
routers without adding it.

Fixed by adding the matching line to the AI & ML section. It sits outside the catalogue
table, so `scripts/check_docs.py` (which compares the README and AGENTS.md tables
row-by-row) is unaffected — re-run green.

### 6 — `AGENTS.md`: the 400-char description budget is not allowlist-only — **fixed**

> `description` — … Keep it within the description budget: **≤250 chars** for most
> skills, **≤400 chars** for the small allowlist of high-traffic skills in
> `scripts/check_descriptions.py`.

The code has a second branch the sentence does not mention:

```python
# scripts/check_descriptions.py
33  ALLOWLIST = frozenset({"architecture-pattern-advisor", "refactoring"})
44      if activation == "router" or name in ALLOWLIST:
45          return ALLOWLIST_BUDGET
```

Routers get 400 without being in `ALLOWLIST`, and neither router is in it. Measured today
the two routers sit at 200 and 203 chars, so nothing is currently mis-sized — the
documented rule is wrong, not the code, and a skill author following the doc would trim a
router description under a limit that does not apply to it.

Fixed by naming the router branch alongside the allowlist.

### 7 — `docs/agents/triage-labels.md`: four of the five labels do not exist — **report only**

The file states it "maps those roles to the actual label strings used in this repo's
issue tracker" and lists `needs-triage`, `needs-info`, `ready-for-agent`,
`ready-for-human`, `wontfix`. Executed against `fabiandistler/agents`:

```console
$ gh label list --limit 60
bug  documentation  duplicate  enhancement  good first issue  help wanted
invalid  question  wontfix  experiment
```

Only `wontfix` exists. `AGENTS.md:185` repeats the same claim ("The five canonical triage
roles use their default label strings"). A skill following this doc would call
`gh issue edit --add-label ready-for-agent` and fail.

**Not fixed here, deliberately.** There are two defensible repairs and they point in
opposite directions: create the four labels in the tracker, or reword the doc to say the
strings are the intended vocabulary rather than the current one. Creating labels changes
the tracker, which is the `doc-drift` analogue of "a code fix to rescue the doc" — per
`references/jobs.md` that makes it a report item, and choosing the direction is the
maintainer's call, not this run's.
