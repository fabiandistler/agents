# Agents

This repository is a catalogue of skills and small utilities for AI coding
agents. It targets any agent that can read Markdown instructions — Claude
Code, Codex CLI, opencode, Continue, Aider, Cursor, and others.

## Start here

- Documentation map: [`docs/README.md`](docs/README.md).
- Add or change a skill: [`docs/contributing.md`](docs/contributing.md);
  [`docs/skill-conventions.md`](docs/skill-conventions.md) is the reference.
- Install and use the catalogue: [`README.md`](README.md) and
  [`docs/install.md`](docs/install.md).
- Vocabulary: [`GLOSSARY.md`](GLOSSARY.md). Decisions:
  [`docs/adr/README.md`](docs/adr/README.md).

## How to use this repo

- Each directory under `skills/` that contains a `SKILL.md` file is a
  self-contained skill.
- `skills.json` (repo root) is the machine-readable manifest of all
  skills. Read it once to discover what is available without crawling the
  tree.
- `install.sh` (repo root) symlinks the skills into the conventional
  install paths for Codex CLI and opencode. It also renders the plugins'
  subagents through `scripts/plugin_agents.py` — Codex custom agents in
  `~/.codex/agents/`, opencode subagents in `~/.config/opencode/agents/` —
  and for Codex CLI disables routed members via a marker-delimited block in
  `~/.codex/config.toml` (all removed by `--uninstall`).
  `--merge-guard` adds the model-free hook `scripts/pr_merge_guard.py` that
  stops agents from merging PRs (only the human merges); this repo's
  `.claude/settings.json` carries it via `scripts/build_project_claude.py`.
  `--secret-guard` adds the same kind of hook, `scripts/secret_read_guard.py`,
  which stops agents from reading credential files or dumping the environment.
  Claude Code gets skills, subagents, the merge guard and the secret read guard
  from the plugin marketplace only; `--target=claude` syncs just
  `--instructions`, installs the guard plugins through the `claude` CLI, and
  removes the links and settings entry older versions created.
  See `./install.sh --help` and `docs/install.md`.
- `instructions/` holds single-topic rule fragments, ordered by numeric
  filename prefix, in three tiers: 20, 25, 45, 50, 55 and 60 are always on;
  Python and R rules are path-scoped in Claude, while Codex and opencode get
  the Python baseline by pointer and keep the R rules in their block; 70, 80
  and 85 are on demand; 85 is also repeated in this repository's `AGENTS.md`.
  `install.sh --instructions` composes the always-on
  rules and pointers into marker-delimited blocks in each agent's global
  instruction file (`~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`,
  `~/.config/opencode/AGENTS.md`) and installs on-demand files under
  `~/.agents/instructions/`. Claude loads `paths:` fragments from
  `~/.claude/rules/`; a `Bash(uv init*)` hook supplies the Python baseline
  before a Python file exists. The 70 and 85 sources live in
  `instructions/on-demand/`; 80 lives at
  `skills/llm-application-engineering/references/agent-pipelines.md`. Content
  outside the managed markers is never touched.
- `plugins/` packages the same skills as Claude plugins, one plugin per
  category (each bundles its skills via symlinks into `skills/`).
  `.claude-plugin/marketplace.json` makes the repo installable as a
  plugin marketplace in Claude Code, claude.ai, Claude Desktop, and
  Cowork. The `architecture` plugin additionally ships two read-only
  analysis subagents (`coupling-analyst`, `cohesion-analyst`). The
  hook-only `merge-guard` and `secret-guard` plugins carry the PR merge
  guard and the secret read guard as `PreToolUse` hooks in `hooks/hooks.json`.
- `.claude/` makes the same skills, subagents and instruction fragments
  available to Claude Code cloud sessions in this repo, which load neither
  plugins nor `~/.claude/`: symlinks and rendered rules generated by
  `scripts/build_project_claude.py` (CI checks drift), including the
  `Bash(uv init*)` hook that reads `instructions/30-python.md`, plus Matt
  Pocock's skills vendored by `scripts/vendor_mattpocock_skills.py`. See
  `docs/maintainers/install-internals.md`.
- Reference material stays inside the skill that owns it, under
  `skills/<skill>/references/`. SKILL.md names the pages it has; an agent
  opens one only when it needs it. There is no lookup service in front of
   them — plain progressive disclosure is the whole mechanism.

## Skill catalogue

Each skill carries a `category` frontmatter field; the sections below
group the catalogue by those categories.

Some categories ship a **router** skill (`activation: router`, named after
the category) as their single registered entry point. Its description is
deliberately broad, and its body routes to the specific sub-skill to read
before acting; the sub-skills nest under the router's `members/` directory
and load only when routed to (progressive disclosure), so the category adds
one trigger entry instead of many. The router's SKILL.md member table is
generated from `skills.json` by `scripts/build_routers.py` (CI checks it for
drift). The tables below still list every sub-skill individually.

## Conventions for skill authors

Read [`docs/skill-conventions.md`](docs/skill-conventions.md) before adding,
renaming or changing a skill, its scripts or references, or a generated file.
It holds the frontmatter fields and description budgets, the generated files
and their regeneration order, the prek hooks and Bats suites, the catalogue
tables and plugin symlinks, the rules for references (tables of contents, dated
claims, table width, paths), the eval prompts, the GitHub-step sentence, and
how Codex keeps router members hidden. `scripts/check_all.sh` enforces most of
them.

## Scripts an agent runs

Applies to any executable an agent invokes: `scripts/` in a skill or
plugin, hook commands, CI helpers. The seven rules that hold outside
this repo too — non-interactive input, `--help`, exit codes, named
writes, secrets, installed smoke test, bounded output — are also carried
globally by `instructions/on-demand/85-agent-scripts.md`; edit both when
they change.

- Never read from an interactive prompt. Agents run non-interactive
  shells; a TTY prompt hangs the session until timeout. Take every input
  as a flag, env var, or stdin. On a missing required input, exit
  non-zero naming the flag and its allowed values.
- `--help` is the agent's only interface documentation — one usage line,
  the flags, two examples. It is also context cost: keep it under ~25
  lines.
- Data to stdout, diagnostics to stderr. Prefer JSON/TSV over
  whitespace-aligned columns.
- Distinct exit code per failure class, documented in `--help`, so the
  caller can branch without parsing prose.
- Idempotent by default: agents retry. "Create if not exists", never
  "fail on duplicate".
- One named verb per write, narrowest stable ID, `--dry-run` first;
  never hide writes in `fix`/`auto`/raw.
- Secrets from env or config, never a flag (shell history, `ps`); never
  echo them, not in `--json` errors. CI flags a skill, instruction or
  script example that passes a credential in argv with
  `python3 scripts/check_secret_argv.py`.
- Smoke-test the installed command from `/tmp`, not the source folder.
- Bound the output. Harness output is truncated past roughly 10–30k
  characters, silently. Default to a summary; offer `--output FILE` and
  `--offset` for the rest.
- Python with third-party deps: PEP 723 inline block + `uv run
  script.py`. No sibling requirements.txt, no install step. `uv add
  --script` to edit, `uv lock --script` when the run must reproduce.
- A one-off command in SKILL.md (`uvx`, `npx`) is version-pinned, or it
  is not a convention.
- Reference bundled skill scripts relative to the skill directory
  (`python3 scripts/tool.py <repo-path>`), never via a repo-root path
  (`skills/<name>/scripts/`, `members/<name>/scripts/`). The skill is
  installed elsewhere, so the target repo is always passed as an argument.
- Every auto or router skill ships eval prompts in `skills/<name>/evals.json`
  (>=3 `should_trigger`, >=1 `should_not_trigger`, optional
  `expected_behavior`; see `docs/adr/0006-skill-eval-prompts.md`). Command
  skills are exempt and may ship one. The `evals` check in
  `scripts/check_all.sh` (the list CI calls) runs `check_evals.py --strict`,
  so a missing or malformed file fails.

## Agent skills

### Issue tracker

Issues live as GitHub issues on fabiandistler/agents, managed via the `gh` CLI. See `docs/agents/issue-tracker.md`.

### Triage labels

The five canonical triage roles use their default label strings (`needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`). See `docs/agents/triage-labels.md`.

### PR review

Pull requests are assessed, reviewed and labeled by `.github/workflows/pr-review.yml`; it never merges. Setup, dry run, rollback and limits: `docs/agents/pr-review-runbook.md`.

### Domain docs

Single-context: one `GLOSSARY.md` + `docs/adr/` at the repo root. See `docs/agents/domain.md`.

### Weekly skill audit

A scheduled Claude Code routine follows `docs/agents/skill-audit.md` every
week: the `repo-error-checker` subagent runs the CI checks repo-wide, and the
`skill-reviewer` subagent judges a rotating quarter of the skills (plus the
most-changed ones) against `docs/agents/skill-audit-checklist.md`. Findings
land in one rolling `skill-audit` issue; mechanical fixes in one
`claude/skill-audit-<date>` PR. Record a finding you decide to keep under the
issue's *Accepted* section so the audit stops reporting it.
