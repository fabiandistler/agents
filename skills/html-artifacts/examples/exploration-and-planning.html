Three ways to implement debounced search

The search box fires one request per keystroke. Each option below delays the request until typing pauses for 250 ms. Same structure in every column, so read across. Recommendation at the bottom: option 02.

OPTION 01

Inline useEffect + setTimeout

Write the timer by hand inside the search component.

useEffect(() => {
  const t = setTimeout(
    () => search(query), 250);
  return () => clearTimeout(t);
}, [query]);

OPTION 02 · RECOMMENDED

useDebouncedValue hook

Extract the timer into a hook; the fetch layer aborts the previous request.

const debounced =
  useDebouncedValue(query, 250);
const results =
  useSearch(debounced); // aborts old

OPTION 03

RxJS debounceTime stream

Model the input as an observable and let operators do the work.

query$.pipe(
  debounceTime(250),
  switchMap(q => search$(q))
).subscribe(setResults);

Recommendation: option 02

It is the only option that fixes the stale-response race without a new dependency. Option 01 would have to be copied into the three other search boxes on the roadmap; option 03 buys the same correctness for 11 kB and a paradigm nobody else in the codebase uses.

Not doing: server-side rate limiting, search-as-you-type suggestions.
