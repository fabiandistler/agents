# Document review and detailed analysis

Read when the input is a long document or deck (Dokumentprüfung), or when the
user asks for the detailed analysis behind the verdict. Output stays German
and phone-readable: lists, no wide tables.

## Document and deck review order

1. Goal, audience, purpose of the decision.
2. Core claim or core message.
3. Structure, red thread, storyline.
4. Central claims and assumptions.
5. Contradictions, gaps, redundancies.
6. Stakeholder risks and objections.
7. Concrete improvements at document level.

For decks, also check:

- Storyline across slides.
- Headlines that state a claim, not a topic.
- Ratio of claim to evidence per slide.
- Slide-to-slide logic.
- Whether the decision slide asks for a decision.

Cite file plus page, slide, or section for every critical point.

## Detailed analysis (on request)

Append after the standard output, under the heading **Detailanalyse**. Keep
only the blocks that carry information.

- **Kontext, Claims, Annahmen**: the frame from step 1 and the key
  assumptions check from step 3, each assumption with belegt / plausibel /
  unbelegt.
- **Steelman**: the 2–3 sentence strongest reading.
- **Stakeholder-Details**: per lens, the objection, the condition under
  which they would agree, and the tendency.
- **Kreuzverhör**, one block per question:
  - Frage: …
  - Warum kritisch: …
  - Belastbare Antwort: …
  - Status: stark / mittel / schwach
- **Risikoliste**, one block per risk:
  - Risiko: …
  - Wahrscheinlichkeit: niedrig / mittel / hoch
  - Wirkung: niedrig / mittel / hoch
  - Frühindikator: …
  - Gegenmaßnahme: …
- **Herleitung des Verdikts**: which surviving material points decide the
  level, and which single point would move it one level up or down.
- **Offene Fragen und Prüfpfade**: what to find out, from whom, by when.
